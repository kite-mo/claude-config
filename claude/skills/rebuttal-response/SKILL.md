# Rebuttal Response

리뷰어 코멘트 하나를 받아 방어 논리 설계부터 영문 초안까지 만든다.

## 작업 절차

### 1. 본질 환원

- 코멘트를 **한 문장 질문으로 환원**한다: "리뷰어가 진짜 묻는 것은?"
- 질문 유형을 분류한다:
  - **why형** (근거/메커니즘 요구) → 실험 나열이 아니라
    "메커니즘 가설 → 검증 가능한 예측 → 확인" 구조가 답이다
  - **신뢰성형** (반복실험/CI/유의성) → 통계 보강
  - **비교형** (baseline/ablation) → 공정한 비교 설계
- 사용자가 제안한 대응 방법이 이 질문에 실제로 답하는지 **먼저 검사**
  한다. 논점 불일치면 구현 전에 지적한다.

### 2. 기존 산출물 매핑

- 실험 폴더·아카이브·기존 노트북에서 이미 답이 되는 산출물을 찾는다.
  **재실험 전에 재사용 가능성부터 확인** (재추론 0회가 이상적).
- 다른 리뷰어 코멘트와의 교차 방어를 확인한다 — 하나의 결과가 두
  코멘트를 동시에 방어하거나(예: NR sweep → 순환성+민감도),
  반대로 한 코멘트 방어가 다른 코멘트를 건드릴 수 있다(모순 주의).

### 3. 신규 실험 설계 시 — 정합성 검사 3종 (구현 전 필수)

1. **자기모순**: 기존 확정 결론과 충돌하지 않는가?
2. **순환성**: 분할/선별 기준이 검증 대상 지표와 같은 양 아닌가?
   (의심되면 상관 직접 계산)
3. **기준점 정렬**: 비교 구조가 지표 정의와 일치하는가?

설계가 통과하면 experiment-notebook 스킬의 4단계 규약으로 정리한다.

### 4. 방어 문장 원칙

- **리뷰어의 전제를 먼저 인정**하고 들어간다 ("attention은 정상 변동으로도
  변한다. 그러나 —"). 과장된 절대 주장(absolutely insensitive)은 금지.
- 크기 논거에는 반드시 독립 축(구조·국소화·물리 일치)을 결합한다.
- 불리한 사례(FP, 경계값, 실패 시드)는 정면 대응한다:
  "왜 그것이 오히려 의도된 동작인지"를 설명하거나, 불가능하면
  한계로 정직하게 명시한다.
- 유리한 수치 선별 제안은 그것이 만들 새 공격면(재현 요구,
  cherry-picking)을 먼저 계산한다. 대표값 교체보다 병기+CI 방어가
  안전한 경우가 많다.
- 문헌 인용으로 "theoretical basis" 지적에 대응할 수 있으면 붙인다.

### 5. 영문 초안 구조

```
We thank the reviewer for this important point.
[1문단: 전제 인정 + 핵심 답 한 문장]
[2문단: 메커니즘/근거 설명]
[3문단: 실험 증거 — 수치·그림 인용 (Fig. X)]
[4문단: 경계 사례 정직 대응 + 원고 반영 위치 (Section X, revised)]
```

- 원고 수정 위치(Section/Figure)를 반드시 지목한다
- 수치는 노트북 실행 출력과 대조된 것만 사용한다
- "we retrained N times" 등 표현은 실제 수행 내용과 정확히 일치시킨다
  (과장 서술은 재현 요구 리스크)

## 주의

- 코멘트 하나에 대응 하나 — 여러 코멘트를 한 실험에 욱여넣지 않는다
  (교차 참조는 허용, 역할 분담은 명확히)
- 보류 항목은 명시적으로 "보류"로 기록하고 아카이브에 남긴다
