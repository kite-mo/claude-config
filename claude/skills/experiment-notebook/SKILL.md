# Experiment Notebook (4단계 규약)

실험/분석 결과를 재현 가능한 실행 상태의 노트북으로 정리한다.

## 작업 절차

### 0. 사전 실측 — 서술 금지 구간

노트북을 쓰기 전에 핵심 수치를 스크래치 계산으로 먼저 확인한다.
예상과 다르면 설계·서사를 수치에 맞춰 조정한다.
**그림/데이터 실측 전 해석 확정 금지.**

### 1. 노트북 구조 (4단계 규약)

각 검증 항목마다 아래 4단계로 압축 서술한다. 검증이 여러 개면
"검증 1", "검증 2"로 나누고 각각 이 구조를 반복한다.

```
# <실험 ID>. <제목> (<대응 리뷰어/문제 코드>)
### ① 리뷰어/문제 피드백    ← 원문 인용 + 본질 한 문장 환원
## 검증 N — <한 줄 주장>
### ② 실험 설계·판정 기준   ← 합격/불합격 조건을 결과 전에 명시
### ③ 결과                  ← 표 + 그림 (raw plot 우선)
### ④ 검증                  ← 판정 기준 대조표(✅) + 한계 정직 기록
## 종합 결론                 ← rebuttal/보고 문장의 뼈대
```

- "why"형 질문 대응이면 ①에 **메커니즘 가설 → 검증 가능한 예측(P1, P2…)**
  을 세우고 각 검증이 예측 하나씩을 담당하게 한다.
- ④에는 관련 실험 cross-reference를 명시한다 (예: "겹침 구간의 정체는
  A-2 검증 2 참조").

### 2. 구현 패턴 (빌더 → 실행)

1. 빌더 스크립트를 scratchpad에 작성 (`nbformat`으로 셀 구성).
   노트북을 직접 json으로 만들지 않는다 — 수정 반복이 쉬워야 한다.
2. `jupyter nbconvert --to notebook --execute --inplace <노트북>` 으로
   실행 상태 저장. (환경: 프로젝트 venv에 nbformat 없으면
   `rules/infra_rule.md` 의 "jupyter 도구" 경로 사용 — 머신마다 다르다)
3. 실행 후 **셀 출력 수치를 markdown 주장과 전수 대조**한다.
4. 저장 그림을 Read로 직접 열어 실측 확인한다.

### 3. 산출물 규칙

- 위치: 해당 실험 폴더 (`experiments/<revision>/<EXP_ID>/`)
- 저장: `<exp>_<주제>.png` (dpi=150) + `<exp>_summary.json` (핵심 수치)
- 일회성 스크립트는 실험 폴더 `scripts/` 아래에 둔다 (src 오염 금지)
- 캐시(재추론 산출물)는 `runs/` 아래 npz/json으로 저장하고
  producer 스크립트 경로를 노트북에 명기한다

### 4. 검증 assert (필수)

기존 확정 산출물(anchor 등)과 겹치는 수치는 반드시 assert로 일치를
강제한다: 점수 allclose, threshold, 라벨 순서, pred 일치.
새 추출 코드는 기존 결과 재현(sanity)을 먼저 통과시킨다.

### 5. 스타일

- 그림 텍스트(title/label/legend)는 영어, markdown·주석은 한국어
- 출판용 산출물의 센서명 등 식별자는 익명화 맵 적용
  (예: `src/config/sensor_name_map.json`)
- 색상 관례: 정상 `#2166ac`(파랑), 이상 `#d95f0e`(주황)
- 분석은 단순하게: raw plot > 통계 요약 > 차원축소 순으로 우선.
  결론에 기여하지 않는 분석은 본문에서 제거 (산출물만 보관)
- 대조군(효과 없어야 할 항목)을 포함해 cherry-picking을 방어한다

## 주의

- 판정 기준을 결과 확인 후에 소급 작성하지 않는다
- 노트북이 장황해지면 "이 중 결론에 필수인 것은?"을 다시 묻고 걷어낸다
- 기존 노트북을 대체할 때 구버전 파일은 삭제하지 말고 커밋 정리 시
  사용자 결정에 맡긴다

## 연계

- 실험 **실행·재현성 관리**(nohup, seed, GPU)는 experiment-runner 스킬 담당.
