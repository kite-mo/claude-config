# Handover Doc

흩어진 분석 자산을 다른 사람이 이어받을 수 있는 형태로 정리한다.

## 작업 절차

### 1. 소스 수집

- 사용자에게 받을 것: 분석 주피터 경로들(차수별), 관련 문서/위키 링크,
  저장 대상 repo 경로, 데이터 공용 경로
- 주피터를 차수(시기)별로 읽고 각 차수에서 **무엇이 바뀌었고 왜**를 추출

### 2. 인수인계 마크다운 구조

```
# <프로젝트명> 인수인계
## 1. 프로젝트 개요        ← 목적, 기간, 결과 요약
## 2. 발전 히스토리         ← 차수별: 시도 → 발견 → 다음 차수로 이어진 이유
## 3. 최종 파이프라인       ← 전처리 → EDA → Feature Engineering
                              → 모델링 → 성능 평가·해석
## 4. 데이터               ← 공용 경로 (원본/전처리), 스키마 요점
## 5. 재현 방법            ← 최종 노트북 실행 순서, 환경
## 6. 한계와 다음 단계
```

- 핵심만 담는다 — 작업 PC 로컬 경로, 폐기된 시도의 세부는 히스토리
  한 줄로만
- 코드는 **최종 버전만** 문서에 반영 (중간 버전은 히스토리 서술로)

### 3. 데이터 공용화

- 원본/전처리 데이터를 공용 서버 경로로 복사
  (경로 규약은 프로젝트 `CLAUDE.md` 또는 `rules/infra_rule.md` 확인.
  관례: `<공용루트>/<프로젝트>/{raw,pre}`)
- 최종 노트북의 데이터 로드 경로를 공용 경로로 수정

### 4. 실행 가능한 최종 노트북

- 차수별 주피터에서 최종 파이프라인만 추출해 **새 노트북**으로 재구성
  (전처리 노트북 / 모델링 노트북 분리 가능)
- 공용 경로 기준으로 처음부터 끝까지 **실제 실행해 오류 없음을 검증**
  한다 (nbconvert --execute). 실행 안 해본 인수인계는 미완성이다.

### 5. 마무리

- 대상 repo에 저장 후 git-manager 스킬로 커밋 정리
- 프로젝트 CLAUDE.md가 있으면 인수인계 상태를 반영해 업데이트
