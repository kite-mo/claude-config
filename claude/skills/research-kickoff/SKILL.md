# Research Kickoff

세션 시작 시 흩어진 컨텍스트(CLAUDE.md, 아카이브, 메모리, 실행 중인
백그라운드 작업)를 한 번에 복원하고, "어디까지 했고 / 지금 무엇이 돌고
있고 / 다음에 무엇을 할지" 브리핑을 제공한다. 연구 프로젝트뿐 아니라
개발·문서·인프라 등 아카이브 기반으로 이어가는 모든 프로젝트에 적용한다.

## 사용 시점

- "작업을 시작하자" / "이어서 하자" / "이전 작업에서 이어서 하고 싶어"
- 프로젝트 CLAUDE.md 경로만 던지고 세션을 시작할 때
- 오랜만에 프로젝트로 복귀해 상태 파악이 필요할 때

## 작업 절차

### 1단계: 프로젝트 컨텍스트 로드

다음 순서로 읽는다 (존재하는 것만):

1. 프로젝트 루트의 `CLAUDE.md`
2. `.claude/archive/` 에서 **날짜순 최신 2개** 아카이브 파일
   ```bash
   ls -t <project>/.claude/archive/*.md | head -2
   ```
3. `~/.claude/projects/<작업디렉토리 슬러그>/memory/MEMORY.md` 에서 해당
   프로젝트 항목과 연결된 상세 메모리 파일. 슬러그는 홈이 아니라 **세션의
   작업 디렉토리**에서 파생된다 (`/` → `-`). 정확한 값은
   `rules/infra_rule.md` 의 memory 항목 참고, 확실치 않으면
   `ls ~/.claude/projects/` 로 확인한다
4. `.claude/rules/` 폴더가 있으면 규칙 파일 확인
5. `.claude/peer_review_comments/` 같은 진행 중 태스크 폴더가
   CLAUDE.md 나 메모리에 언급되어 있으면 핵심 문서만 확인

### 2단계: 실행 중인 작업 상태 확인

장시간 백그라운드 작업(실험, 빌드, 배치 처리 등)이 돌고 있을 수
있으므로 반드시 확인한다:

```bash
# nohup 백그라운드 프로세스
ps aux | grep -E "python.*(run_|train)|nohup" | grep -v grep

# GPU 사용 프로젝트라면 점유 상태 (GPU 없는 머신에서는 건너뜀)
command -v nvidia-smi >/dev/null && \
    nvidia-smi --query-gpu=index,memory.used,memory.total --format=csv

# 진행 상황 트래킹 파일 (있는 경우)
cat <project>/experiments/**/progress.json 2>/dev/null
```

프로젝트에 자체 상태 확인 스크립트가 있으면 그것을 쓴다
(프로젝트 `CLAUDE.md` 에서 확인):
```bash
.venv/bin/python <상태확인 스크립트>
```

### 3단계: 브리핑 제공

수집한 정보를 다음 형식으로 요약한다:

```markdown
## 📋 세션 브리핑

**마지막 세션** (날짜): 한 일 요약 2~3줄
**현재 실행 중**: GPU별 실험 상태 (없으면 "없음")
**미해결/주의 사항**: 최신 아카이브의 "다음 단계" 항목
**제안하는 오늘 작업**: 1~2개 (우선순위 근거 포함)
```

마감이 있는 프로젝트(예: 논문 revision)는 남은 기간을 브리핑 첫 줄에
명시한다.

### 4단계: 사용자 확인 후 작업 시작

브리핑 후 사용자가 방향을 정하면 작업을 시작한다.
제안은 여러 옵션 나열보다 **근거 있는 단일 추천**을 우선한다.

## 주의사항

- 아카이브가 많아도 최신 2개만 읽는다 (토큰 절약). 과거 세션이 필요하면
  파일명(날짜_주제)으로 검색 후 해당 파일만 추가로 읽는다.
- 메모리에 기록된 원칙(seed, 재현성, 저장 경로 등)은 브리핑에서 재확인하고
  이후 작업의 기본값으로 적용한다.
- 세션 종료 시 session-archiver 로 아카이브하는 것을 잊지 않도록,
  큰 작업 단위가 끝나면 아카이브를 먼저 제안한다.
